The AI components need a server route to talk to the AI model. This recipe
adds one to your app at `app/api/editor-ai/route.ts`. It uses the Vercel AI SDK
and Vercel AI Gateway, and keeps your API key on the server.

<Callout type="info" title="The demos on this site use this recipe">
  The editors on this site run this exact route. The only difference is that
  they use OpenRouter's free models (`openrouter/free`) instead of the Gateway.
</Callout>

## Before you start

Make sure your project has everything below before you add the route.

- At least one emend AI component in your app
- A Next.js app that uses the App Router
- A Vercel AI Gateway API key
- A way to check who is signed in, so you can protect the route

## Install the route

First complete [Installation](/docs/installation) to add the `@emend` registry.

```npm
npx shadcn@latest add @emend/recipe-vercel-ai-gateway
```

This adds one file, `app/api/editor-ai/route.ts`, which you can edit. It uses
the `openai/gpt-5.6-luna` model by default. It gives the model different
instructions for questions and for edits.

## What the route does

- `createEmendAiHandler` checks each request, rejects requests that are too
  large, and streams the answer back to the browser.
- `generate` is the only part that calls the AI provider. To use a different
  model, change `MODEL`. To use a different provider, replace `streamText` with
  any Vercel AI SDK provider. Nothing else needs to change.

## Add your API key

```bash title=".env.local"
AI_GATEWAY_API_KEY=your_server_side_key
```

Do not start the name with `NEXT_PUBLIC_`, and never pass the key to a client
component. Either would expose it in the browser.

## Connect your components

Create a transport with the route's URL and pass it to your AI component.

```tsx title="app/editor/page.tsx"
"use client"

import { createFetchTransport } from "@emend/ai/transport"
import { EmendEditor } from "@/components/emend/emend-editor/emend-editor"

const transport = createFetchTransport({ url: "/api/editor-ai" }) // [!code highlight]

export default function EditorPage() {
  return <EmendEditor transport={transport} />
}
```

## Protect the route

Right now, anyone who finds the URL can call the route and use your AI
credits. Add an `authorize` check that uses your app's existing sign-in logic:

{/* prettier-ignore */}
```ts title="app/api/editor-ai/route.ts"
export const POST = createEmendAiHandler({
  authorize: async (request) => { // [!code ++]
    return userCanEdit(await getCurrentUser(request)) // [!code ++]
  }, // [!code ++]
  async *generate(request, signal) {
    // Keep the installed Gateway generator here.
  },
})
```

Replace `getCurrentUser` and `userCanEdit` with the functions your app already
uses to check sign-in and permissions.

You should also limit how many requests each user can make, before the AI model
is called. The recipe does not include rate limits, because only your app knows
who your users are and what they are allowed to use.

## What you should see

- A valid request to `/api/editor-ai` streams the AI's answer back.
- An invalid request returns an [emend error](/docs/api-reference/error-codes).
- A request with too much text returns `413`.
- After you add `authorize`, a request from someone not allowed returns `401`.
