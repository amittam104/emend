Emend uses two pieces together: the Shadcn registry copies the UI source into
your project, while `@emend/ai` supplies the protocol, controller, Tiptap
integration, and transports shared by every AI surface.

<Callout type="warn" title="Public installation is not available yet">
  `@emend/ai` remains unpublished. Registry commands that include AI will not
  complete from the public npm registry until the preview package is released.
  The same flow is verified today with a packed package in clean consumer
  fixtures.
</Callout>

## Prerequisites

- Next.js App Router and React 19
- Tiptap packages aligned to `3.30.1`
- Shadcn initialized with Tailwind CSS 4
- Node.js `24.19.0` or later
- A server route for any AI-enabled surface

## Set up your project

<Steps>
<Step>

### Add the registry

Add the `@emend` namespace to the `components.json` that Shadcn created:

```jsonc title="components.json"
{
  "$schema": "https://ui.shadcn.com/schema.json",
  "style": "new-york",
  "tailwind": { "css": "app/globals.css" },
  "registries": { // [!code ++]
    "@emend": "https://emend.dev/r/{name}.json" // [!code ++]
  } // [!code ++]
}
```

Use `http://127.0.0.1:3000/r/{name}.json` instead when working against a local
checkout of this repository.

</Step>
<Step>

### Install the runtime

Install the `@emend/ai` runtime with the package manager you use in your
project.

```npm
npm install @emend/ai
```

</Step>
<Step>

### Add one registry item

The Bubble Menu is the smallest AI-enabled starting point:

```npm
npx shadcn@latest add @emend/ai-bubble-menu
```

Shadcn reads the generated registry item, installs only its declared
dependencies, and copies the component into
`components/emend/ai-bubble-menu`. The copied UI belongs to your application;
shared editing behavior continues to come from `@emend/ai`.

</Step>
</Steps>

## Expected result

You should have editable component source under `components/emend`, normal
Shadcn primitives under `components/ui`, and no dependency on Emend's private
monorepo packages.
