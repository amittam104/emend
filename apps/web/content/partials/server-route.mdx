The AI components do not call the AI model from the browser. They send each
request to a server route in your app, and that route calls the model. This
keeps your API key secret. The [Vercel AI Gateway recipe](/docs/vercel-ai-gateway)
adds a ready-made route at `app/api/editor-ai/route.ts`.

<Steps>
<Step>

### Add the route

```npm
npx shadcn@latest add @emend/recipe-vercel-ai-gateway
```

</Step>
<Step>

### Add your server key

```bash title=".env.local"
AI_GATEWAY_API_KEY=your_server_side_key
```

Do not start the name with `NEXT_PUBLIC_`. That would send the key to the
browser. If you deploy on Vercel, you can skip the key and use Vercel OIDC.

</Step>
<Step>

### Look at the route

This is the file the command adds to your app. `createEmendAiHandler` checks
each request and streams the answer back. The `generate` function is the only
part that talks to the AI provider, so change it to use a different model or
provider.

<include lang="ts" meta='title="app/api/editor-ai/route.ts"'>../../../../registry/recipes/vercel-ai-gateway/route.ts</include>

</Step>
<Step>

### Connect your component to the route

A transport tells a component which URL to send requests to. The examples on
this page already use `/api/editor-ai`. Change it only if you move the route.

```tsx
const transport = createFetchTransport({ url: "/api/editor-ai" }) // [!code highlight]
```

</Step>
</Steps>

Before you go live, make sure only signed-in users can call the route, and
limit how often they can call it. See
[Protect the route](/docs/vercel-ai-gateway#protect-the-route).
